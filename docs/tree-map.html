Carland service — code tree map

Every package, class and public method that does real work in this Spring Boot service, each with a plain-English description. The "N checks" badge on a method links to its validation ladder in validations.html. Getters, setters, constructors and boilerplate are omitted.

com.carland.carland_service.security The gate of the service. These filters and validators run before any controller — they check tokens and webhook signatures, so their checks are always the first ones a request meets.
ContentCachingFilterWraps every request so its body can be read more than once (needed for signature checking and then again by the controller). Runs at highest precedence.
Wraps the request in a re-readable body wrapper and continues the chain.doFilterInternal(request, response, filterChain)no checks
CustomFilterSecurity filter on every request; lets webhook and public paths (Swagger, admin UI, legal, etc.) through and returns 401 when the Authorization: Bearer header is missing on protected paths. Actual JWT validation happens at the Kong gateway.
Inspects the request path, lets public/webhook paths through, otherwise requires a Bearer token before continuing.doFilterInternal(request, response, filterChain)1 check
WebhookSignatureFilterAuthentication filter for /webhook/partner/* requests; validates the internal service token first, then the partner's HMAC signature, and writes a 401 JSON response on failure.
Runs the internal-token and HMAC-signature validations in order; either failure stops the request with 401.doFilterInternal(request, response, filterChain)2 checks
InternalTokenValidatorValidates the X-Internal-Token header of service-to-service webhook requests against configuration, using a constant-time comparison.
Checks that the internal token is configured, present and matching; returns a success or failure result.validate(request)3 checks
PartnerWebhookSignatureServicePerforms the HMAC signature validation of partner webhook requests: resolves the partner, checks it is active and configured, then verifies the X-Signature header.
Resolves the partner from the request and verifies the request signature step by step.validate(request, body)6 checks
HmacSignatureValidatorComputes and compares HMAC-SHA256 signatures for webhook requests, in constant time to resist timing attacks.
Decides what data to sign: the body when present, otherwise the sorted query parameters.resolvePayload(request, body)no checks
Computes the expected signature and compares it with the one the partner sent.isValid(secret, payload, providedSignature)3 checks
Returns a short fingerprint of the payload, used only for debugging in logs.sha256Prefix(payload)no checks
WebhookAuthResponseWriterProduces the 401 JSON response when webhook authentication fails; puts the error code into the X-Webhook-Auth-Error header.
Builds the error body from a validation result and writes it as a 401 response.writeUnauthorized(response, result)no checks
Writes a 401 response from failure info alone, without a partner id.writeUnauthorized(response, failure)no checks
