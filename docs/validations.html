Carland service — validations and checks

Every validation, guard and precondition each function runs, in the order they execute (cheapest first: authentication → input shape → ownership → business rules → database checks). Each check has a stable rule ID and the HTTP status returned when it fails. Statuses come from the exception handlers: MissingFieldException, InvalidStatusException, NotMatchException, FileStorageException → 400; UserNotFoundException, ResourceNotFoundException → 404; AlreadyExistsException, ConflictException → 409; webhook auth failures → 401. Structure mirrors tree-map.html one to one.

4xx client error (red) 422 unprocessable (amber — none currently in this codebase) 5xx server error no error redirect or handled internally

com.carland.carland_service.security

These checks run before any controller code — they are the first rungs of every request's ladder.

ContentCachingFilter

Wraps every request so its body can be read more than once.

doFilterInternal(request, response, filterChain)Wraps the request in a re-readable body wrapper and continues the chain.
  1. no checks
  2. all passed → proceeds

CustomFilter

Security filter on every request; webhook and public paths (Swagger, admin UI, legal pages, exports…) pass through freely.

doFilterInternal(request, response, filterChain)Requires a Bearer token on protected paths; webhook and public paths are exempt.
  1. SEC-001Does the request carry an "Authorization: Bearer …" header? (Skipped for webhook and public paths.)401 unauthorized
  2. all passed → proceeds

WebhookSignatureFilter

Authentication filter for /webhook/partner/* requests; both checks below delegate to the validators further down.

doFilterInternal(request, response, filterChain)Runs internal-token then HMAC-signature validation; either failure ends the request with a 401 JSON body.
  1. SEC-002Is the internal service token valid? (Details in InternalTokenValidator.validate.)401 unauthorized
  2. SEC-003Is the partner's HMAC signature valid? (Details in PartnerWebhookSignatureService.validate; skipped for the /test path.)401 unauthorized
  3. all passed → proceeds

InternalTokenValidator

Validates the X-Internal-Token header using a constant-time comparison.

validate(request)Checks that the internal token is configured, present and matching.
  1. SEC-004Is an internal token configured on the server at all?401 internal_token_not_configured
  2. SEC-005Did the request send the X-Internal-Token header?401 missing_internal_token
  3. SEC-006Does the provided token match the configured one (constant-time comparison)?401 invalid_internal_token
  4. all passed → proceeds

PartnerWebhookSignatureService

HMAC signature validation of partner webhook requests.

validate(request, body)Resolves the partner from the request and verifies the request signature.
  1. SEC-007Can a partnerId be found in the query string or the request body?401 missing_partner_id
  2. SEC-008Does a partner with this id exist?401 partner_not_found
  3. SEC-009Is the partner active?401 partner_inactive
  4. SEC-010Does the partner have a webhook secret configured?401 secret_not_configured
  5. SEC-011Did the request send the X-Signature header?401 missing_signature_header
  6. SEC-012Does the HMAC-SHA256 signature of the payload match the header value?401 invalid_signature
  7. all passed → proceeds

HmacSignatureValidator

Computes and compares HMAC-SHA256 signatures in constant time.

resolvePayload(request, body)Chooses what to sign: the body when present, otherwise the sorted query parameters.
  1. no checks
  2. all passed → proceeds
isValid(secret, payload, providedSignature)Computes the expected signature and compares it with the one the partner sent. A failed check makes the method return false, which the caller reports as 401 invalid_signature.
  1. SEC-013Are both the secret and the provided signature non-blank?401 invalid_signature (via caller)
  2. SEC-014Is the provided signature valid hexadecimal?401 invalid_signature (via caller)
  3. SEC-015Does the computed HMAC equal the provided one (constant-time comparison)?401 invalid_signature (via caller)
  4. all passed → proceeds
sha256Prefix(payload)Returns a short fingerprint of the payload for debug logging.
  1. no checks
  2. all passed → proceeds

WebhookAuthResponseWriter

Writes the 401 JSON response when webhook authentication fails.

writeUnauthorized(response, result)Builds the error body from a validation result and writes it as a 401 response.
  1. no checks
  2. all passed → proceeds
writeUnauthorized(response, failure)Writes a 401 response from failure info alone, without a partner id.
  1. no checks
  2. all passed → proceeds
