1. Genel bakış

Architecture

Flutter SIMA’yı doğrudan çağırmaz. HMAC secret sadece backend’de kalır. Mobile bizim KYC API’lerimize gider; backend SIMA’ya proxy + imza + sonuç kaydı yapar.

1
Flutter FIN + documentNumber/birthDate + selfie toplar
2
POST /api/v1/kyc/sima/verify (Bearer JWT) → CarCat backend
3
Backend minify JSON + HMAC-SHA256 imzalar
4
POST {SIMA}/api/v1/kyc/identity/verify
5
Gate: isSuccess && livenessStatus && similarityStatus
6
DB’ye FIN metadata yaz · selfie discard · response dön
7
GET /api/v1/kyc/status ile UI durumu günceller
Dikkat: Bu dokümanda “şifreleme” kelimesi HMAC imza anlamına gelir. Body AES ile şifrelenmez. SIMA, minify edilmiş JSON body’nin HMAC-SHA256 Base64 hash’ini Signature header’ında ister.

FIN = pin

7 karakterlik kişisel kimlik numarası. SIMA request body alanı: pin. CarCat tarafında alan adı genelde fin.

2. HMAC imzalama (server-side only)

SIMA Auth

HyperService HMAC ailesiyle aynı tuzak: imzaladığın baytlar ≠ gönderdiğin baytlar ise hash uyuşmaz.

Adımlar

  1. Request body map oluştur (idempotencyKey dahil, her istekte yeni UUID).
  2. JSON’u bir kez minify et — whitespace yok, pretty-print kapalı.
  3. Aynı minified string’i hem HMAC’le hem HTTP body olarak gönder.
  4. Auth-Scheme: HMACSHA256 (veya SIMA’nın verdiği HMACSHA1).
  5. HMAC-SHA256(secretKey, minifiedBodyBytes) → Base64 → Signature.
  6. Identifier = partner id (SIMA’dan alınan int/string).

Pretty → Minified örnek

Pretty (İMZALAMA) 
// BUNU İMZALAMA — whitespace yüzünden hash kırılır
{
  "pin": "10AAABC",
  "documentNumber": "AA0012345",
  "livePhoto": "ImageBASE64",
  "idempotencyKey": "3c166e1a-9bff-414c-8e0d-aefe97cd33e4"
}
Minified (DOĞRU — imza + send) 
{"pin":"10AAABC","documentNumber":"AA0012345","livePhoto":"ImageBASE64","idempotencyKey":"3c166e1a-9bff-414c-8e0d-aefe97cd33e4"}

Java (Spring) örnek mantık

// 1) minify bir kez
String body = objectMapper.writeValueAsString(requestDto); // SerializationFeature.INDENT_OUTPUT kapalı

// 2) HMAC
Mac mac = Mac.getInstance("HmacSHA256");
mac.init(new SecretKeySpec(secret.getBytes(StandardCharsets.UTF_8), "HmacSHA256"));
byte[] raw = mac.doFinal(body.getBytes(StandardCharsets.UTF_8));
String signature = Base64.getEncoder().encodeToString(raw);

// 3) aynı body'yi gönder
headers.set("Content-Type", "application/json");
headers.set("Auth-Scheme", "HMACSHA256");
headers.set("Signature", signature);
headers.set("Identifier", identifier);
restClient.post().uri(url).headers(h -> h.addAll(headers)).body(body)...;
Asla: Flutter’a HMAC key koyma · Signature’ı client üretme · selfie’yi loglama · isSuccess=true görünce hemen verified yazma.

3. CarCat API — KYC Verify

Mobile → Backend

Mobile’ın çağırdığı ana endpoint. Path proje convention’ına göre uyarlanabilir; kontrat budur.

POST /api/v1/kyc/sima/verify Bearer JWT
POST
/api/v1/kyc/sima/verify

Headers

NameTypeDescription
Authorization required string Bearer <access_token | register_token> — kullanıcı kimliği buradan alınır.
Content-Type required string application/json
Accept-Language optional string Örn. az / tr — hata mesajı dili.
X-Client-Timezone optional string Örn. Asia/Baku

Request body

FieldTypeDescription
fin required string FIN (= SIMA pin). 7 karakter.
documentNumber XOR string | null Vesika no. Yeni nesil: AA/AB prefix. Eski: AZE strip.
birthDate XOR string | null yyyy-MM-dd. documentNumber ile tam biri dolu olmalı.
livePhotoBase64 required string JPEG selfie base64 (data-URI prefix’siz tercih edilir).
XOR kuralı: documentNumber doluysa birthDate = null. Tersi de geçerli. İkisi birden veya ikisi boş → 400 (SIMA 713/714 öncesi bizde yakala).

Request example

POST /api/v1/kyc/sima/verify HTTP/1.1
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Type: application/json
Accept-Language: az

{
  "fin": "10AAABC",
  "documentNumber": "AA0012345",
  "birthDate": null,
  "livePhotoBase64": "/9j/4AAQSkZJRgABAQAAAQABAAD/2wBDA..."
}

Backend iç işlem sırası

  1. JWT → userId
  2. Input validate (FIN, XOR, photo boş değil)
  3. FIN collision: başka verified hesapta varsa → 409
  4. UUID idempotencyKey üret
  5. SIMA body map: pin=fin, livePhoto=livePhotoBase64, …
  6. Minify + HMAC + SIMA call
  7. Gate: isSuccess && livenessStatus && similarityStatus
  8. OK → DB update (finVerified=true + scores + transactionId); selfie discard
  9. Fail → verified=false + mapped code; DB’ye verified yazma

Response 200 — verified

{
  "verified": true,
  "fin": "10AAABC",
  "name": "ARAZ",
  "surname": "ƏLIYEV",
  "patronymic": "ANAR OĞLU",
  "livenessScore": 0.9904,
  "similarityScore": 0.9998,
  "transactionId": "100550",
  "finVerifiedAt": "2026-08-05T10:15:00Z"
}

Response 200 — not verified (business fail)

Teknik 5xx değil. SIMA biometric fail kullanıcıya business response olarak döner. 

{
  "verified": false,
  "code": "SIMA_752",
  "message": "Üz uyğun gəlmədi. Yenidən cəhd edin.",
  "simaErrorCode": 752,
  "transactionId": "100551"
}

Diğer HTTP status

HTTPNe zamanBody örneği
400 Validation / XOR ihlali code: VALIDATION_ERROR
401 JWT yok / geçersiz standart auth error
409 FIN başka verified hesapta code: FIN_COLLISION
429 Rate limit code: RATE_LIMITED
502 / 503 SIMA 710/750/timeout (sistem) code: SIMA_UNAVAILABLE — generic mesaj

409 example

{
  "verified": false,
  "code": "FIN_COLLISION",
  "message": "Bu FIN artıq başqa hesaba bağlıdır."
}

5. SIMA API — Verify Citizen Identity

Backend → SIMA

AzInTelecom resmi endpoint. Sadece server-side çağrılır. Base URL staging/prod SIMA’dan alınır.

POST {SIMA_BASE_URL}/api/v1/kyc/identity/verify
POST
{SIMA_BASE_URL}/api/v1/kyc/identity/verify

Headers

NameTypeDescription
Content-Type required string application/json
Identifier required int / string Partner identifier (SIMA issued).
Auth-Scheme required string Tam olarak HMACSHA256 veya HMACSHA1.
Signature required string Minified body HMAC → Base64.
DeviceInfo optional string Ek cihaz bilgisi.

Request body schema

FieldTypeDescription
pin required string Personal Identification Number (FIN).
documentNumber XOR string | null Vesika no. Yeni: AA/AB. Eski: AZE prefix kaldır.
birthDate XOR date | null yyyy-MM-dd. documentNumber ile XOR.
livePhoto required string Image Base64.
idempotencyKey required string (UUID) Her request’te yeni. Body içinde; header değil. İmzaya dahildir.

6. Hata kodları & CarCat mapping

Errors

SIMA error.errorCode → bizim API code + kullanıcı mesajı.

SIMA code Anlam CarCat code HTTP Kullanıcıya
722 Bu FIN/vesika için aktif kayıt yok SIMA_722 200 Kayıt bulunamadı, tekrar dene
721 Vesikada foto yok SIMA_721 200 Doğrulama yapılamaz (net mesaj)
751 Liveness fail SIMA_751 200 Yeni selfie (ışık/mesafe)
752 Similarity fail SIMA_752 200 Yüz eşleşmedi — 1 retry
7530 Birden fazla yüz SIMA_7530 200 Tek yüz iste
7080–7082 Foto/base64 sorunlu SIMA_708x 200 / 400 Yeniden çek
713 / 714 documentNumber / birthDate kuralı VALIDATION_ERROR 400 Alanları düzelt
70002 Validation exception VALIDATION_ERROR 400 Input kontrol
710 Access not allowed SIMA_UNAVAILABLE 502 Generic — credential/config, kullanıcıya detay yok
750 Biometric service error SIMA_UNAVAILABLE 502 Backoff retry + support log
70000 / 716 Unexpected / system SIMA_UNAVAILABLE 502 Generic
70001 Not authorized (imza?) SIMA_UNAVAILABLE 502 Minify/HMAC kontrol et — alert

7. Foto / livePhoto kuralları

Flutter enforce

Capture tarafında enforce edilmezse fail rate backend’e yansır.

  • Yüz kadrajın %70–80’i; kenardan min 20px boşluk
  • Tek yüz (7530 aksi halde)
  • Format: JPEG
  • Çözünürlük: 640×480 – 1080×1920; dosya ≤ 1 MB
  • Face bounding box genişliği > 200px
  • Kafa pozu pitch/yaw/roll ±20°
  • Nötr ifade, gözler açık, kamera bakışı
  • Filtre / crop / mask yok — sadece downscale izinli
Saklama: livePhoto DB/disk/S3/log’a yazılmaz. Sadece skor + transactionId + FIN metadata kalır.
